# Đồng bộ sang repo team

Repo này là **nguồn duy nhất**. Repo của team (Bitbucket nội bộ Bosch) là **bản sinh ra** từ đây bởi
`tools/TeamExport`: không có comment trong code, không có `docs/`/`tests/`/`.claude/`/`CLAUDE.md`, và
`appsettings.json` đã được biến đổi (chỉ đăng nhập IdentityServer, không có kênh SMTP `Email`).

Luồng chỉ đi **một chiều**. Sau khi bỏ comment, gần như file `.cs` nào ở hai repo cũng khác nhau, nên
merge qua lại bằng git (fork, subtree, cherry-pick) sẽ conflict ở mọi file. Tool không merge mà **ghi đè**:
mỗi lần đồng bộ, toàn bộ file đang được theo dõi ở repo team được thay bằng bản xuất từ commit hiện tại
của repo này. Nếu ai đó sửa trực tiếp bên team thì lần đồng bộ sau sẽ xoá mất. Thay đổi phải đi qua
repo này.

## Chạy

Lần đầu, clone repo team về một thư mục **bên cạnh** repo này (không được nằm trong repo này):

```bash
git clone <url-bitbucket-repo-team> ../ICOGenerator-team
```

Mỗi lần muốn đẩy code sang team (chạy từ thư mục gốc repo này, cả hai repo phải sạch, không còn thay
đổi chưa commit):

```bash
git -C ../ICOGenerator-team pull
dotnet run --project tools/TeamExport -- --target ../ICOGenerator-team --commit
git -C ../ICOGenerator-team push
```

Tool làm theo thứ tự sau:

1. Kiểm tra cả hai repo đều sạch (tắt bằng `--allow-dirty`), và thư mục đích là gốc một git repo khác repo này.
2. Xoá mọi file **git đang theo dõi** ở repo team, trừ các file khớp `preserveInTarget`. `bin/`, `obj/` không bị đụng tới.
3. Lấy danh sách file từ `git ls-files` của repo này (nên file bị `.gitignore` không bao giờ lọt sang),
   bỏ các file khớp `exclude`, xoá comment, biến đổi JSON, lọc `.sln`, rồi ghi sang repo team.
4. Chép đè các file trong `tools/TeamExport/overlay/` (README riêng cho team).
5. Chạy `dotnet build` trên bản xuất. Build fail thì dừng, **không commit**, file vẫn để ở đích để xem (bỏ bước này bằng `--no-build`).
6. Với `--commit`: commit vào repo team kèm danh sách commit nguồn kể từ lần đồng bộ trước và dòng
   `Source-Commit: <sha>`. Tool dựa vào dòng này để biết lần sau bắt đầu từ đâu. Thêm `--push` để push luôn.

Không có `--commit` thì tool chỉ ghi file. Có thể xem trước bằng `git -C ../ICOGenerator-team diff`.

## Cấu hình: `tools/TeamExport/team-export.json`

| Mục | Ý nghĩa |
|---|---|
| `exclude` | Glob các file **không** đưa sang team. Hiện tại: `docs/**`, `tests/**`, `.claude/**`, `CLAUDE.md`, `tools/**`. |
| `stripCommentExtensions` | Đuôi file bị xoá comment: `.cs`, `.cshtml`, `.js`, `.css`, `.csproj`. |
| `stripCommentExclude` | Glob các file giữ nguyên comment dù có đuôi nằm trong danh sách trên. |
| `keepCommentsContaining` | Comment chứa chuỗi này thì giữ lại. `<auto-generated` là bắt buộc: thiếu header đó, file migration bị analyzer/nullable soi như code viết tay. |
| `jsonTransforms` | Luật biến đổi từng file JSON (xem bên dưới). |
| `overlayDirectory` | Thư mục chứa file chép đè lên bản xuất (`overlay/README.md`). |
| `preserveInTarget` | Glob các file chỉ có bên repo team (vd `bitbucket-pipelines.yml`), không bị xoá khi đồng bộ. |

### Biến đổi `appsettings.json`

Repo team không giữ một bản `appsettings.json` chép tay, vì bản đó sẽ lệch ngay khi bên này thêm key mới.
Tool lấy file của repo này rồi áp các luật sau:

- `removeKeysStartingWith: "_"`: bỏ mọi key `_note`, `_noteTls`, ... ở mọi cấp (chúng cũng là comment).
- `remove`: bỏ `Notifications:Email`, `Authentication:LocalUsername`, `Authentication:LocalRole`.
- `set`: `Authentication:Provider = IdentityServer`; `Encryption:ApiKeyKey = ""`, vì khóa nạp qua biến
  môi trường `Encryption__ApiKeyKey` và không được đi theo file.

Đường dẫn key viết theo kiểu cấu hình ASP.NET Core (`Section:Key`). Key mới thêm ở repo này tự sang team.
Chỉ khi key đó phải **khác** bên team thì mới thêm luật. Nếu đổi tên hoặc xoá một key mà luật đang trỏ tới,
`ExportConfigTests.TeamExportRulesStillMatchAppsettings` sẽ fail lúc `dotnet test`. Lúc chạy export, tool
cũng in cảnh báo.

Code vẫn giữ nguyên provider `Local` và kênh `Email`, vì đó là lựa chọn bằng cấu hình chứ không phải hai
bản code. Bên team, `Email` không được cấu hình nên kênh đó tắt, giống như khi `Enabled = false`.

## Xoá comment làm thế nào và được kiểm ra sao

Tool không dùng regex. Mỗi ngôn ngữ dùng một bộ đọc biết ngữ pháp (`tools/TeamExport/Stripping/`):

| Loại file | Cách tìm comment | Chốt kiểm |
|---|---|---|
| `.cs` | Roslyn: comment trivia, cả doc comment `///` | Parse lại, so **từng token** với bản gốc; lệch thì dừng. |
| `.js` | Acornima (parser JS): phân biệt regex `/\/\//`, chuỗi, template literal với comment | Tokenize lại và so với bản gốc. |
| `.css` | Quét chuỗi + `/* */` | Không có chốt riêng; giữ nguyên comment `/*! ... */`. |
| `.cshtml` | Bộ quét Razor tối giản: `@* *@`, `<!-- -->`, `//` và `/* */` trong khối `@{ }`/`@functions`/thân `@if...`, comment JS trong `<script>` (biểu thức Razor được che trước khi đưa cho parser JS), comment CSS trong `<style>` | Mỗi đoạn bị xoá phải mở đầu bằng cú pháp comment; `dotnet build` biên dịch lại toàn bộ view. |
| `.csproj` | `<!-- -->` ngoài CDATA | `dotnet build`. |

Comment chiếm trọn một dòng thì cả dòng bị bỏ. Comment cuối dòng thì bỏ luôn khoảng trắng đứng trước nó.
Dòng trống đôi do việc xoá để lại được gộp làm một. Tool giữ nguyên BOM và kiểu xuống dòng (CRLF/LF) của
từng file.

Những thứ **cố ý không** bị xoá:

- `//` nằm **trong chuỗi**. Ví dụ đoạn JavaScript nhúng trong raw string C# ở
  `Services/Artifacts/PocRuntimeChecker.cs`: đó là dữ liệu gửi cho trình duyệt, không phải comment C#.
- `Prompts/**` (`.md`, `.html`): đây là nội dung prompt gửi cho LLM. Đổi chúng là đổi hành vi agent.
- Nếu một `<script>` inline có cấu trúc Razor phức tạp (`@if` lồng trong script) mà parser JS không đọc
  được, tool giữ nguyên comment của riêng khối đó và in cảnh báo.

## Sửa tool

- Code ở `tools/TeamExport/`, là một project console riêng. `ICOGenerator.csproj` loại trừ `tools/**`
  nên tool không bị biên dịch vào app.
- Test ở `tests/ICOGenerator.Tests/TeamExport/`. Có các ca dễ nhầm nhất của từng ngôn ngữ (URL trong
  markup, regex chứa `//`, `@:` trong khối code...), cộng với hai test chốt cấu hình thật: luật
  `appsettings` còn khớp, và `.sln` xuất ra không còn project test/tool.
- Thêm một thư mục mới ở gốc repo thì quyết định luôn: thư mục đó có sang team không (`exclude`), và
  đuôi file của nó có cần xoá comment không (`stripCommentExtensions`).
